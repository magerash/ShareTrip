# Environment — the machine, the procedures, and what goes wrong

Everything about the world *outside* the source code: versions, binaries, ports, commands,
and the failure modes that have actually happened.

**This is the layer that rots silently.** The code tells you when it is wrong — it fails to
compile, the test goes red. The environment does not: it just quietly describes a machine
nobody has any more, and the next person loses an afternoon to it. So every fact here was
established by **running something**, not by assuming, and each one is dated. Re-verify
anything you are about to depend on heavily.

**An environment document that was never re-run is a guess with a date on it.**

---

## Run it

```bash
python3 -m http.server 8000 --directory web    # затем http://localhost:8000
```

| | |
|---|---|
| приложение | `http://localhost:8000` — логотип ShareTrip и кнопка «Создать поездку». Если поездка уже есть, сразу открывается лента трат. |
| тесты | `node --test "tests/*.test.mjs"` — должно быть `# pass 63`, `# fail 0`. |
| живая проверка | `npm run smoke` — 21 шаг · `npm run layout` — 32 проверки прокрутки · `npm run form` — 14 проверок формы. Везде `0 провалено`. |
| вики | `python3 tools/wiki/check-links.py && python3 tools/wiki/wiki-doctor.py` — 0 битых ссылок, 0 отказов. |

**Что нужно свежему клону перед первой командой: ничего.** Ни `npm install`, ни сборки, ни
ключей, ни сети. Клиент — нативные ES-модули (D-009), и любой статический сервер их отдаёт.
`python3 -m http.server` берётся только потому, что он уже есть; подойдёт любой другой.

Единственное, чего нельзя, — открыть `web/index.html` двойным кликом как `file://`: браузер
запрещает ES-модули и IndexedDB на этой схеме. Нужен именно http.

## Живая проверка в браузере

Скрипт `smoke.mjs` (в рабочем каталоге сессии, не в репозитории — строка 7 доски предлагает
перенести его в `tests/`) поднимает статический сервер на случайном порту, открывает
Chromium окном 840×1180 (примерно планшет в портрете) и проходит сценарий целиком:
создание поездки → счёт в AZN → обмен → трата картой партнёра → итог → перезагрузка →
запись расчёта → выгрузка CSV. Дополнительно проверяет, что в разметке нет текстовых узлов
«null» и что нигде не угадывается род по имени.

```bash
npm install playwright          # один раз, в рабочем каталоге вне репозитория
node smoke.mjs
```

Playwright ищет браузер по `PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`. Ставить браузеры
командой `playwright install` не нужно и не следует — они уже есть.

## Развёртывание на VPS (ещё не выполнено — строка 10 доски)

Канонический документ машины — `C:\Projects\VPS-monitor\docs\vps-architecture.md`.
Здесь только то, что добавляет ShareTrip. **Сборки нет**, поэтому выкладка — это копирование
каталога `web/`; ни `node_modules`, ни артефактов сборки на сервере не появляется.

Предполагаемая раскладка (по образцу соседнего проекта):

```
/opt/sharetrip
  web/            собранного ничего нет — каталог web/ из репозитория как есть
  web.prev/       предыдущая версия, чтобы откатиться копированием
  sharetrip.caddy отрендеренный блок; его копия внутри /etc/caddy/Caddyfile
```

Правила машины, унаследованные и обязательные:

- **Никогда не `cat >` поверх `/etc/caddy/Caddyfile`.** В нём живут десять чужих сайтов.
  Только дописывать между `# ===== BEGIN sharetrip =====` и `# ===== END sharetrip =====`.
- **`caddy validate`, затем `chown caddy:caddy /var/log/caddy/access.log`, затем
  `systemctl reload caddy`.** Валидация под root пересоздаёт лог с неправильным владельцем,
  и *следующая* перезагрузка молча падает. `reload`, никогда `restart`.
- **Коды соседей до и после.** Выкладка обязана обойти все остальные сайты curl-ом и упасть
  на любом расхождении.
- **Каждый публикуемый порт — `127.0.0.1:`.** Docker обходит хостовый файрвол; привязка и
  есть контроль, `ss -tlnp` после выкладки — доказательство.

ShareTrip своих контейнеров и портов **не занимает**: это статические файлы, которые отдаёт
уже работающий Caddy через `file_server`. Памяти на VPS он не потребляет вовсе. Это изменится
только на строке 9 доски (синхронизация через Supabase) — тогда понадобится пара
GoTrue + PostgREST и два порта из зарезервированных.

## Failure modes — то, что уже случалось

| Симптом | Причина | Что делать |
|---|---|---|
| «Добавил трату, перезагрузил — долг исчез» | Сохранение было отложено на 300 мс, `pagehide` не успевает дождаться транзакции IndexedDB | Исправлено немедленной записью (D-008). Если повторится — смотреть `persist()` в `store.js`, не возвращать задержку |
| На экране расчёта текст «null» | Нативный `el.append(null)` вставляет строку «null» | Условные потомки вставлять только через `mount()` из `ui.js` |
| «Хранилище недоступно» на старте | Режим инкогнито или запрет сайту хранить данные | Открыть в обычном окне. Приложение честно говорит об этом, а не делает вид, что сохраняет |
| Кнопка «CSV — всё» ничего не делает | Песочница просмотрщика блокирует `<a download>` | Приложение определяет это (`canDownload`) и показывает текст для копирования (A-002) |
| Excel показал кракозябры и склеил колонки | CSV открыт без BOM или с разделителем «,» | Выгрузка пишет BOM и `;`. Если правили `csv.js` — проверить оба |
| Пустая страница, в консоли ошибка модуля | Открыли `web/index.html` как `file://` | Поднять http-сервер |
| Итог показывает «курс не задан» | В поездке появилась валюта без курса | Вкладка «Ещё» → «Курсы валют». Сеть за курсом не пойдёт никогда (D-004) |
