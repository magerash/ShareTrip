# Запуск и выкладка

**Две машины**, один и тот же каталог `web/`. Сборки нет (D-009), поэтому «выложить» везде
означает «положить файлы туда, откуда их отдаёт веб-сервер».

| Где | Чем | Зачем |
|---|---|---|
| Домашний компьютер (Jonsbo, Windows) | `infra\serve.cmd` или Docker | разработка, работа с ботом, адрес в домашней сети |
| VPS | `infra/deploy-vps.sh` | доступ извне, с телефона в поездке |

Домашний компьютер в корпусе Jonsbo — это и рабочая машина, и то, что раздаёт приложение по
домашней сети. Отдельного домашнего сервера нет, и заводить его не нужно: для двух человек
хватает одного процесса.

**Что проверено, а что нет.** Локальный сервер (`infra/serve.mjs`) запускался и отвечал:
`index.html` и модули отдаются с верными типами, выход за пределы каталога получает 404.
Docker-стек и скрипт выкладки на VPS **не запускались ни разу** — в этом окружении не было
ни демона Docker, ни доступа к серверу. Проверен только синтаксис: `docker compose config`
разбирает файл, `bash -n` разбирает скрипт. Первый настоящий запуск делайте при себе.

## ⚠️ Почему общий адрес ещё не значит общие данные

Это главное, что нужно понять до выкладки, потому что интуиция подсказывает обратное.

**ShareTrip хранит поездку в браузере того устройства, где её завели** — в IndexedDB
(D-006). Сервер отдаёт только файлы приложения. Он не видит ваших трат, не хранит их и не
может передать другому человеку.

Отсюда следует то, что легко принять за поломку:

- Открыли один и тот же адрес на планшете и на телефоне — **это две разные поездки.**
  Пустая на телефоне, ваша на планшете.
- Ксюша и Вова открыли один адрес с разных устройств — **у каждого свой отдельный учёт.**
  Они будут молча расходиться, и в конце поездки цифры не сойдутся.
- Почистили историю браузера или открыли в режиме инкогнито — **данных нет.**

Это не обойти ни выкладкой на VPS, ни доменом, ни HTTPS. Пока данные лежат в браузере,
общий у двоих только внешний вид приложения.

**Что с этим делать сегодня:** вести поездку на одном устройстве — это нормальный режим для
пары, когда планшет лежит на столе. Переносить данные другому — через «Ещё» → «Резервная
копия» и «Восстановить». Копию стоит делать в конце каждого дня: это единственное, что
защищает от чистки браузера.

**Что с этим делать по-настоящему:** нужна серверная база — одна на двоих, с которой оба
устройства синхронизируются. Проект для этого уже размечен: см.
[specs/sync.md](specs/sync.md) и строку 9 доски. Пока она не сделана, «общий доступ» честнее
называть «общим приложением», а не «общим учётом».

## Домашний компьютер (Jonsbo, Windows)

> Разворачиваете в первый раз или передаёте задачу агенту на той машине —
> [handoff-jonsbo.md](handoff-jonsbo.md): пошагово, с проверкой на каждом шаге и честным
> списком того, что на Windows ещё никто не запускал.

Это и рабочая машина, и то, что раздаёт приложение по домашней сети. Нужен только
[Node.js 20+](https://nodejs.org): ни сборки, ни ключей.

### Как приложение сюда попадает

```bash
git clone https://github.com/magerash/ShareTrip
cd ShareTrip
npm install        # одна зависимость, и только для браузерных проверок
npm test           # убедиться, что всё зелёное
```

Никакого «переноса» сверх этого нет: репозиторий самодостаточен, собирать нечего.

**Данные при этом не переезжают.** Они лежат в браузере того устройства, где заведены. Чтобы
забрать поездку с планшета, выгрузите её там («Ещё» → «Резервная копия») и восстановите здесь
через «Восстановить».

### Запуск

```
infra\serve.cmd
```

Двойной клик. Откроется `http://localhost:8080`, браузер запустится сам. Остановить — `Ctrl+C`
в появившемся окне.

Чтобы открыть с телефона или планшета в той же Wi-Fi-сети:

```
infra\serve-lan.cmd
```

Скрипт напечатает адрес вида `http://192.168.1.50:8080`. Помните про раздел выше: это тот же
адрес, но **не те же данные**.

> Открыть `web\index.html` двойным кликом нельзя. Браузер запрещает ES-модули и IndexedDB на
> схеме `file://`, и приложение просто не запустится. Нужен именно http.

Оба `.cmd` переключают консоль в UTF-8 (`chcp 65001`) — без этого `cmd.exe` показывает
кириллицу кракозябрами.

### Постоянный адрес: Docker на той же машине

Если не хочется каждый раз запускать `serve.cmd`, поднимите контейнер: он переживает
перезагрузку и раздаёт приложение, пока компьютер включён. Это **та же самая машина**, просто
другой способ её запустить — отдельного сервера заводить не нужно.

```bash
docker compose -f infra/docker-compose.yml up -d
docker compose -f infra/docker-compose.yml logs -f      # посмотреть, что происходит
docker compose -f infra/docker-compose.yml down         # остановить
```

Открывается на `http://<адрес-компьютера>:8080`. Порт меняется левым числом в строке
`"8080:8080"` файла `infra/docker-compose.yml`, если 8080 уже занят.

Обновление после правки кода: `git pull`, затем

```bash
docker compose -f infra/docker-compose.yml restart
```

Пересобирать нечего — каталог `web/` подключён томом только для чтения, контейнер видит файлы
напрямую. Лимит 64 МБ: сайт статический, больше ему не нужно.

**Про HTTPS.** Caddy здесь настроен на `auto_https off` и отдаёт по http: имени и сертификата
у домашнего компьютера обычно нет. Для PWA это значит, что «установить приложение» и
service worker работать не будут — браузеры требуют https или localhost. Само приложение
работает полностью; не будет только офлайн-кэша, а считает оно всё равно на устройстве.

### Работа с ботом

```
npm test          # 63 случая: денежное ядро, модель расчёта, выгрузка, даты
npm run smoke     # живой прогон в Chromium по реальному интерфейсу
npm run layout    # прокрутка доезжает до конца
npm run form      # форма траты: что на виду и что сохраняется
npm run wiki      # ссылки и регламент вики
npm run check     # тесты + вики
```

Перед тем как менять код, прочитайте [AGENTS.md](../AGENTS.md): там несущие факты, каждый из
которых уже однажды был нарушен.

## VPS

На этой машине уже работает Caddy на `:8443` с **одним общим Caddyfile**, в котором живут
десять чужих сайтов. Поэтому ShareTrip не поднимает ни своего веб-сервера, ни контейнера:
он добавляет блок в общий файл и кладёт файлы в `/opt/sharetrip/web`. Памяти он не
занимает вовсе — это важно на машине, где свободно около 2,4 ГБ.

### Настройка

```bash
cp infra/deploy.env.example infra/deploy.env
# заполнить SSH_TARGET, SITE_HOST, NEIGHBOURS
```

`infra/deploy.env` в git не попадает: адреса и имя машины — настройка, а не текст
репозитория.

### Выкладка

```bash
./infra/deploy-vps.sh --dry-run     # сначала всегда так
./infra/deploy-vps.sh               # только файлы
./infra/deploy-vps.sh --recaddy     # файлы и блок Caddy (нужно один раз)
./infra/deploy-vps.sh --rollback    # вернуть предыдущую версию
```

Что скрипт делает по порядку:

1. Гоняет тесты локально. Красные тесты отменяют выкладку.
2. Снимает коды соседних сайтов **до**.
3. Сохраняет текущую версию в `web.prev` и копирует новую через `rsync`.
4. С `--recaddy`: делает копию Caddyfile, заменяет **только** свой блок между
   `# ===== BEGIN sharetrip =====` и `# ===== END sharetrip =====`, затем
   `caddy validate` → `chown caddy:caddy /var/log/caddy/access.log` → `systemctl reload caddy`.
5. Снимает коды соседей **после** и падает на любом расхождении.
6. Печатает слушающие порты и свободную память.

### Правила машины, которые нарушать нельзя

- **Никогда `cat >` поверх `/etc/caddy/Caddyfile`.** В нём десять чужих сайтов. Только
  замена своего блока между маркерами.
- **Порядок `validate` → `chown` → `reload` обязателен.** Валидация под root пересоздаёт
  файл лога с владельцем `root`, и тогда *следующая* перезагрузка падает молча. `chown`
  между ними — не суеверие, а лечение конкретного отказа.
- **`reload`, никогда `restart`.** Перезапуск рвёт соединения всем сайтам машины.
- **Соседи сверяются до и после.** Сосед, который изменился, — это наша выкладка, даже
  когда неочевидно как.
- **Порты 443 и 8444 занимает xray.** Трогать их нельзя; все сайты живут на `:8443`.

Полный контекст машины — `C:\Projects\VPS-monitor\docs\vps-architecture.md`; здесь только
то, что добавляет ShareTrip. См. также [environment.md](environment.md).

## Порядок, в котором стоит идти

1. **Домашний компьютер, `serve.cmd`** — убедиться, что приложение запускается и тесты зелёные.
2. **Он же, но через Docker** — если нужен постоянный адрес в домашней сети, а не запуск руками.
3. **VPS** — когда нужен доступ снаружи, из поездки.
4. **Синхронизация** ([specs/sync.md](specs/sync.md)) — когда нужно, чтобы двое вели
   **один** учёт, а не два похожих. Без этого шага пункты 2 и 3 дают общий адрес, но не
   общие данные.
