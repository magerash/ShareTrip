# ShareTrip — project wiki

Synthesised memory. The context window is RAM; this folder is disk. **Search is `grep` and
`read` over `docs/`** — there is no index to build and no service to run.

**Stack:** Vanilla ES modules, no build step; IndexedDB local-first; served as static files by Caddy file_server; Supabase (Postgres 17 + PostgREST + GoTrue) planned for sync
**Run:** `python3 -m http.server 8000 --directory web` · **Test:** `python3 -m http.server 8000 --directory web  # then open /tests/` — the full runbook is [environment.md](environment.md).

## Before you touch anything — the preflight

Four checks, under a minute. Each one exists because skipping it has cost somebody a day.

1. **`git status`.** The working tree can be ahead of this wiki. Work half-built in an
   uncommitted diff has been re-started from scratch by the next session more than once.
2. **The board.** [ROADMAP.md](ROADMAP.md) — is anything `▶`? If so, somebody is on it;
   pick a different row or name your lane.
3. **The last two chunks.** [sessions/README.md](sessions/README.md), newest first. They
   say what the previous session left on the floor, which this file's summaries will not.
4. **The open questions.** The `B-` section of [DECISIONS.md](DECISIONS.md) — you may be
   about to spend a day on something that is blocked for a reason somebody already found.

## Update regulation (mandatory)

**Step 0 before you start; steps 1–6 after every feature or iteration.** Not optional:
without it the wiki goes stale and stops being worth reading, and a wiki nobody trusts is
worse than no wiki, because people act on it anyway.

0. **Status, before the first edit.** Set the row you are about to work on in
   [ROADMAP.md](ROADMAP.md) to `▶`. One row at a time. When you stop, set the status that
   is *true* — `✅` finished and verifiable, `⏸` **with what remains and where it is** —
   and never back to `☐`. It costs one character. It is the cheapest step here and the one
   most often skipped, and the failure it prevents is expensive: a row that reads "not
   started" is an invitation, so the next session builds the thing you are halfway through.
1. **Session chunk.** Write `sessions/NN-slug/2026-09-15-topic.md`: *what was done, how it
   works, what was decided and why*, and a **Next** block. One chunk per feature or
   iteration. Use `python3 tools/wiki/new-session.py "topic"` to open a new session folder —
   it claims the number without racing another agent and writes the index rows for you.
2. **Synthesis into the documents.** Update whatever the change touched:
   [code-map.md](code-map.md) for new or moved paths, and the ledger for anything decided.
   **A new decision, assumption or blocker is a new numbered entry** in
   [DECISIONS.md](DECISIONS.md) — you supersede an old entry, you never rewrite it.
   History that gets edited stops being evidence.
3. **Environment.** Did a version, a path, a port, a command or a procedure change? Did you
   hit a failure mode nobody had written down? Then [environment.md](environment.md).
   **This is the step that rots silently:** the code tells you when it is wrong, the
   environment does not. It is also the step that costs the next person an afternoon.
4. **Indexes, then the checkers.** A row in the [session table](#sessions) and, for a new
   concept, a row in [concept → where to look](#concept--where-to-look). Then:
   ```bash
   python3 tools/wiki/check-links.py && python3 tools/wiki/wiki-doctor.py
   ```
   Both must be clean. They are fast and they are the only things in this repo that read
   a link or re-derive a count.
5. **Local tool memory.** If a fact matters *between* sessions, put a short **pointer** in
   your own tool's memory — never a copy of this wiki. Copies drift; the wiki is canonical.
6. **The commit.** Subject `vX.Y.Z Name of the session's work` — the version copied from
   the `Open:` line of `docs/changelog.md`, never bumped here. Body: one emoji bullet per
   change with the number that was wrong and the alternative rejected, a `📚 Wiki —` line, a
   `✅` line with the instruments (if one could not run, say so there), the ids last. A
   short list, roughly twenty lines at most — the reasoning is the chunk. A `wiki-artefact`
   project has no version and writes `type(scope): the name` as its subject; the body is the
   same. The commit gate enforces this.

Decisions, assumptions and blockers are addressable — `D-nnn`, `A-nnn`, `B-n`. **Cite the
id; do not restate the content.** A decision paraphrased into three documents is three
documents that will eventually disagree.

## Document map

Every document has exactly one job. A fact lives in one place; everything else cites it.

| Document | Owns | Never carries |
|---|---|---|
| [README.md](README.md) *(this file)* | the way in — the regulation, the maps, the session table | anything that belongs in a document below |
| [code-map.md](code-map.md) | **where things are** — every path and what it is for | why, or what is planned |
| [DECISIONS.md](DECISIONS.md) | **why** — numbered, append-only, cited by id from code and commits | narrative, status |
| [ROADMAP.md](ROADMAP.md) | **what, in what order, and where it stands** | the content of the work |
| [environment.md](environment.md) | **the machine and the procedures** — versions, ports, commands, failure modes | anything that binds the code |
| [sessions/](sessions/README.md) | **what actually happened**, dated | anything forward-looking |

When the two layers disagree: a **chunk wins about what happened**, a **synthesis document
wins about how things are now**.

**This file has a budget: 200 lines.** Over it, `wiki-doctor.py` fails. The entry point is
read at the start of every session by every agent and every person, and an entry point that
does not fit in a glance stops being read at all — which is how a 244 KB index happens.
When it strains, move the session table to `sessions/README.md` and the concept index to
its own file, and leave pointers here.

## Concept → where to look

Phrase each row as the question a reader actually arrives with — *"why does X go wrong"*,
not *"X subsystem overview"*. This is the section people skip and the one that pays.

| I want to understand… | Look at |
|---|---|
| How to run it, and what breaks when I do | [environment.md](environment.md) |
| Where a given piece of behaviour lives | [code-map.md](code-map.md) |
| Why it was built this way and not the obvious way | [DECISIONS.md](DECISIONS.md) |
| What is being worked on right now | [ROADMAP.md](ROADMAP.md) — the `▶` rows |
