# Хендофф: развернуть ShareTrip на домашнем компьютере

**Кому:** агенту, который работает на домашнем компьютере (корпус Jonsbo, Windows).
**Задача:** поднять приложение локально, убедиться, что оно работает, и оставить машину в
состоянии, из которого можно вести разработку.

Этот файл писал агент, который делал проект в Linux-контейнере. **Windows он не видел
никогда.** Ниже прямо помечено, что проверено, а что нет: там, где написано «не проверялось»,
нужно проверить, а не поверить.

---

## 0. Что это за проект, в одном абзаце

ShareTrip — трекер трат для поездки вдвоём: мультивалютные счета, курс, который вводит
человек и который замораживается в операции, и прямой ответ «кто кому должен» с полной
разбивкой. **Сборки нет и сети не нужно**: клиент — нативные ES-модули, которые любой
статический сервер отдаёт как есть, а все деньги считаются на устройстве целыми копейками.
Развернуть — значит отдать каталог `web/` по http.

Канон — вики в `docs/`. **Начните с [README.md](README.md)** (регламент и карта документов) и
[AGENTS.md](../AGENTS.md) (правила репозитория и несущие факты, каждый из которых уже однажды
был нарушен).

## 1. Что нужно на машине

| | Зачем | Обязательно? |
|---|---|---|
| **Node.js 20+** | запустить приложение и прогнать тесты | да |
| **Git** | забрать репозиторий | да |
| **Python 3.9+** | проверки вики и хуки Claude Code | желательно |
| **Docker Desktop** | постоянный адрес в домашней сети | нет |

Про Python: приложение без него работает полностью. Без него не работают `npm run wiki` и
хуки (в том числе гейт, который не пускает коммит с красной вики). Если ставите — включите
при установке **«Add python.exe to PATH»**.

> ⚠️ **Ловушка Windows, уже учтённая в коде.** В командной строке Windows `python3` — это шим
> из Microsoft Store, который ничего не выполняет. Поэтому все вызовы идут через обёртку
> `tools/wiki/py.mjs`: она пробует `py -3`, затем `python3`, затем `python`, и берёт первый,
> который реально отвечает. Не возвращайте прямые вызовы `python3` в `package.json` или в
> `.claude/settings.json` — на этой машине они молча умрут.

## 2. Развернуть — по шагам

Каждый шаг заканчивается проверкой. Не переходите к следующему, пока предыдущий не дал
ожидаемый вывод.

### Шаг 1. Забрать репозиторий

```
git clone https://github.com/magerash/ShareTrip
cd ShareTrip
git checkout claude/app-performance-optimization-gaj9ii
```

Работа лежит в этой ветке, не в `main`.

**Проверка:** `git log --oneline -1` печатает коммит с темой `v0.1.0 …`.

### Шаг 2. Зависимости

```
npm install
```

Зависимость ровно одна — Playwright, и только для браузерных проверок. **Он тянет Chromium,
это сотни мегабайт и несколько минут.** Если сейчас это не нужно:

```
npm install --ignore-scripts
```

Тогда `npm test` работать будет, а `npm run smoke|layout|form` — нет, пока не выполните
`npx playwright install chromium`.

**Проверка:** `npm test` печатает `# pass 63` и `# fail 0`. Браузер для этого не нужен.

### Шаг 3. Запустить

```
infra\serve.cmd
```

Двойной клик тоже работает. Скрипт откроет `http://localhost:8080` и сам запустит браузер.

**Проверка:** открылась заставка ShareTrip с кнопкой «Создать поездку». Создайте поездку,
добавьте трату — она должна появиться в ленте, а на вкладке «Итог» должна быть строка
«кто → кому».

> **Не открывайте `web\index.html` двойным кликом.** Браузер запрещает ES-модули и IndexedDB
> на схеме `file://`, приложение не запустится. Нужен именно http.

**Не проверялось на Windows:** сам `serve.cmd`. Сервер `infra/serve.mjs`, который он
вызывает, запускался и отвечал (верные типы, выход за каталог → 404), но в Linux. Если
`.cmd` не отработает, запустите напрямую и сообщите, что именно сломалось:

```
node infra\serve.mjs
```

Известные места, где `.cmd` может споткнуться: `chcp 65001` (без него кириллица в консоли
превратится в кракозябры — на работу приложения не влияет), `where node`, `start "" http://…`.

### Шаг 4. Убедиться, что всё зелёное

```
npm run verify
```

Это `npm test` + три браузерных прогона + вики. Ожидаемо:

```
# pass 63, # fail 0
форма:      20 успешно, 0 провалено
прокрутка:  32 проверки
сценарий:   21 шаг, 0 ошибок в консоли
вики:       10 проверок, 0 отказов; 107 ссылок, 0 битых
```

**Не проверялось на Windows:** браузерные прогоны. Скрипты сначала пробуют путь к Chromium
этого контейнера, а при неудаче переходят на обычный запуск Playwright — на Windows должна
сработать вторая ветка. Если нет, задайте путь явно: `set CHROME_PATH=...` и запустите снова.

## 3. Перенести данные с планшета

**Данные не переезжают вместе с кодом.** Поездка живёт в IndexedDB того браузера, где
заведена; сервер её не видит и передать не может — это свойство, а не недоделка
([deploy.md](deploy.md), раздел «Общий адрес не значит общие данные»).

1. На планшете: «Ещё» → **«Резервная копия»**. Если браузер не даст скачать файл, приложение
   покажет текст — скопируйте его и сохраните в `.json`.
2. На компьютере: «Ещё» → **«Восстановить»** → выберите файл.

Поездки с тем же идентификатором заменятся, остальные добавятся; без спроса ничего не
удаляется.

## 4. Постоянный адрес в домашней сети (необязательно)

Если не хочется каждый раз запускать `serve.cmd`:

```
docker compose -f infra/docker-compose.yml up -d
```

Откроется на `http://<адрес-компьютера>:8080` и переживёт перезагрузку. Это **та же самая
машина**, просто другой способ её запустить — отдельный сервер заводить не нужно.

**Не проверялось вообще:** Docker-стек ни разу не запускался, в том контейнере не было
демона. Проверен только синтаксис (`docker compose config`). Если упадёт — смотрите
`docker compose -f infra/docker-compose.yml logs`.

Чтобы открыть с телефона без Docker: `infra\serve-lan.cmd` — напечатает адрес вида
`http://192.168.1.50:8080`.

## 5. Правила, по которым здесь работают

Полностью — в [AGENTS.md](../AGENTS.md) и `.claude/rules/`. Самое важное для первой сессии:

- **Git — только по команде.** Никаких коммитов «чтобы сохранить». `CB` = закоммитить и
  запушить, `NB` = то же плюс новая ветка, `Let's finish` = закрыть итерацию (git не
  трогает). Ничто другое git не трогает.
- **Перед первой правкой отметьте строку на доске** `▶` в [ROADMAP.md](ROADMAP.md).
- **Деньги — целые копейки, курс заморожен.** Ни одного числа с плавающей точкой в хранимых
  данных; пересчитывать `amountHome` задним числом нельзя.
- **Условных потомков вставляйте только через `mount()`** — нативный `append(null)` рисует на
  экране слово «null».
- **Измеряйте, а не утверждайте.** Две вещи намеренно нигде не заявлены, потому что не
  измерены: скорость (нет тайминга) и «ввод за 2–3 касания» (нет счётчика касаний). Это
  строки 7 и 8 доски. Если беретесь — начните с прибора, а не с оптимизации.

## 7. Первое, что стоит сделать после запуска

По убыванию пользы:

1. **Пройти шаги 2–4 и сообщить, что из «не проверялось» сломалось.** Это самая ценная
   информация: её нельзя получить нигде, кроме этой машины.
2. **Строка 7 доски — измерить скорость.** Снять базис: время до первой отрисовки и от
   нажатия «Сохранить» до факта записи в IndexedDB. Пока числа нет, слово «быстро» остаётся
   рекламой, и в репозитории его намеренно нет.
3. **Строка 9 — синхронизация.** Единственное, что превращает «общее приложение» в «общий
   учёт». Контракт уже написан, включая критерий приёмки: два устройства офлайн вводят по
   десять операций, после обмена документы совпадают побайтово.
